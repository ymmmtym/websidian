## 概要

Linux でメモリ・CPU・ディスク・ネットワークなどのリソース状況を確認する監視コマンドの使い方と、用途別の選び方をまとめます。

## `free -h` の見方

`free -h` は Linux でメモリ（RAM）の使用状況を確認するコマンドです。`-h` オプションは「human-readable」の略で、数字を Mi（メビバイト）、Gi（ギビバイト）などの読みやすい単位で表示します。

### Mem（物理メモリ）

| 項目 | 意味 |
|------|------|
| **total** | 搭載している物理メモリの総量です。 |
| **used** | 使用中のメモリ量です。 |
| **free** | 完全に未使用のメモリ量です。 |
| **shared** | 複数のプロセス間で共有されているメモリ量です。 |
| **buff/cache** | ディスク読み書きを高速化するためのバッファ・キャッシュに使われているメモリです。 |
| **available** | 新しくプロセスが確保可能なメモリ量です。 |

### Swap（スワップ領域）

| 項目 | 意味 |
|------|------|
| **total / used / free** | ディスク上に確保された仮想メモリ領域です。`0B` の場合はスワップが無効または未設定です。 |

### 読み取りのポイント

- `used` と `free` だけ見ると少なく見えますが、実際には `buff/cache` に確保されている分もプロセスが必要になれば解放されるため、**実質的な空きは `available` で判断するのが正確**です。
- `buff/cache` は Linux がディスクアクセスを速くするために自動的に使っているメモリなので、「メモリが逼迫している」とは限りません。
- スワップが `0B` の場合、メモリ不足になった際にディスクを使った仮想メモリによる救済ができません。メモリが足りなくなると OOM Killer（Out Of Memory Killer）が動作してプロセスを強制終了させる可能性があります。

## CPU・プロセス監視

### `top`

リアルタイムでプロセスとリソース使用状況を表示します。

```bash
top
```

表示中の操作：

- `P`：CPU 使用率順にソートします。
- `M`：メモリ使用率順にソートします。
- `1`：CPU コアごとの使用率を表示します。
- `q`：終了します。

### `htop`

`top` のカラー版で、視覚的に見やすく、マウス操作も可能です（インストールが必要な場合あり）。

```bash
htop
```

### `ps`

特定時点のプロセス一覧を表示します。

```bash
ps aux               # 全プロセスの詳細表示
ps aux | grep nginx  # nginx 関連のプロセスを絞り込み
```

## メモリ監視

### `free -h`

現在のメモリ使用状況を確認します。

```bash
free -h
```

### `vmstat`

メモリ、プロセス、CPU、I/O などを包括的に監視できます。

```bash
vmstat 1 5   # 1秒間隔で5回出力
```

主な表示列の意味：

- `r`：実行待ちのプロセス数です。
- `b`：スリープ中のプロセス数です。
- `si` / `so`：スワップイン / スワップアウトです。
- `us` / `sy` / `id` / `wa`：ユーザー時間 / システム時間 / アイドル / I/O待ちです。

## ディスク監視

### `df -h`

ファイルシステムのディスク容量を確認します。

```bash
df -h
```

### `du`

ディレクトリやファイルの使用量を確認します。

```bash
du -sh /var/log       # /var/log の合計サイズのみ表示
du -h --max-depth=1   # カレントディレクトリの直下フォルダごとの使用量
```

### `iostat`

ディスク I/O の統計情報を確認します（sysstat パッケージに含まれる場合あり）。

```bash
iostat -x 1           # 拡張統計を1秒間隔で表示
```

## ネットワーク監視

### `ss`

`netstat` の代替として現代ではこちらが推奨されます。ソケット（ネットワーク接続）の状態を確認します。

```bash
ss -tuln              # リッスン中の TCP/UDP ポートを表示
ss -tunap             # プロセス名付きで全接続を表示（root権限推奨）
```

### `iftop` / `nload`

リアルタイムのネットワーク帯域使用状況を監視します。

```bash
sudo iftop            # 通信相手ごとの帯域を表示
nload                 # シンプルな入出力帯域表示
```

### `ping`

ホストへの到達性と遅延を確認します。

```bash
ping 8.8.8.8
```

### `mtr`

`ping` と `traceroute` を組み合わせたような、経路とパケットロスを継続的に監視するツールです（インストールが必要な場合あり）。

```bash
mtr 8.8.8.8
```

## システム全体・負荷監視

### `uptime`

システムの稼働時間と平均負荷（load average）を確認します。

```bash
uptime
```

出力例：

```
14:30:00 up 5 days, 2:15, 1 user, load average: 0.52, 0.58, 0.59
```

`load average` の3つの数字は、それぞれ **1分前 / 5分前 / 15分前** の平均負荷です。負荷値が CPU コア数を超えると処理が追いついていない可能性があります。

### `sar`

過去のシステム統計を確認できる強力なツールです（sysstat パッケージに含まれます）。

```bash
sar -u 1 5            # CPU 使用率を1秒間隔で5回
sar -r 1 5            # メモリ使用率を1秒間隔で5回
```

## ログ・カーネル監視

### `dmesg`

カーネルリングバッファのメッセージを確認します（ハードウェア関連のエラーなど）。

```bash
dmesg | tail -20
dmesg -w              # リアルタイムで新規メッセージを監視
```

### `journalctl`

systemd 使用時のシステムログを確認します。

```bash
journalctl -xe                        # 最新ログを詳細表示
journalctl -u nginx --since "1 hour ago"  # nginx サービスの最近1時間のログ
journalctl -f                         # tail -f 相当のリアルタイム監視
```

## その他の便利な監視ワンライナー

```bash
# カレントディレクトリのファイル・ディレクトリ数
ls | wc -l

# 開いているファイルの数（上限に近づいていないか確認）
lsof | wc -l
ulimit -n             # プロセスあたりのファイルディスクリプタ上限

# 各プロセスのメモリ使用量ランキング
ps aux --sort=-%mem | head -10

# 各プロセスの CPU 使用率ランキング
ps aux --sort=-%cpu | head -10
```

## まとめ

| 確認したいこと | おすすめコマンド |
|---|---|
| メモリ足りてる？ | `free -h` |
| CPU 使いすぎ？ | `top`, `ps aux --sort=-%cpu` |
| ディスク残量？ | `df -h` |
| ディスク重い？ | `iostat -x 1` |
| ネットワーク繋がる？ | `ping`, `ss -tuln` |
| 通信帯域？ | `iftop`, `nload` |
| システム負荷？ | `uptime`, `vmstat 1` |
| ログに異常？ | `journalctl -xe`, `dmesg` |
