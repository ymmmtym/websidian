## 概要

Webアプリ・サーバーアプリの両方に対応し、言語に依存しない共通基盤と言語固有の実装テンプレートを定義します。エージェントが要件を満たすアプリケーションを自律生成できるようにすることが目的です。

## 共通基盤要件

言語やアプリケーション種別に関わらず、すべてのプロジェクトに適用される基盤要件を定義します。エージェントはこれらをデフォルトで含めた状態で開発を開始します。

### CI / CD パイプライン

- プッシュ・プルリクエスト時に自動テストを実行します。
- テストカバレッジレポートを自動生成します（目標 70% 以上）。
- ビルド成果物を自動でアーティファクト化します。
- ステージング / 本番への自動デプロイを設定します（オプトイン）。

### コンテナ化

- Dockerfile の多言語テンプレートを用意します（軽量イメージベース）。
- docker-compose.yml を用意します（ローカル開発・統合テスト用）。
- マルチステージビルドでビルド環境と実行環境を分離します。
- 非 root ユーザーでコンテナを実行します。

### セキュリティチェック

- 依存ライブラリの脆弱性スキャンを実行します（Dependabot / Snyk 等）。
- 静的解析（SAST）ツールを組み込みます。
- シークレット検出を設定します（pre-commit フック or CI ステップ）。
- コンテナイメージスキャンを実行します（Trivy 等）。
- CSP / CORS / セキュリティヘッダーを標準設定します。

### 品質ゲート

- Lint でコードスタイルを統一します。
- Type Check で型安全性を検証します。
- Format Check でフォーマッタ適用を確認します。
- テスト失敗時はマージをブロックします。

## Webアプリケーションテンプレート

フロントエンドを含む Web アプリケーション向けテンプレートです。フレームワークに依存しない共通構造と、主要フレームワーク別の拡張を定義します。

### ディレクトリ構成

```
web-app-template/
├── .github/
│   └── workflows/
│       └── ci.yml
├── docker/
│   ├── Dockerfile
│   └── docker-compose.yml
├── src/
│   ├── components/       # UI コンポーネント
│   ├── pages/            # ページ単位モジュール
│   ├── hooks/            # カスタムフック
│   ├── lib/              # ユーティリティ
│   ├── styles/           # グローバルスタイル
│   └── types/            # 型定義
├── tests/
│   ├── unit/             # ユニットテスト
│   ├── integration/      # 統合テスト
│   └── e2e/              # E2Eテスト
├── public/               # 静的アセット
├── docs/                 # アーキテクチャ決定記録
├── .env.example
├── .eslintrc / biome.json / etc.
├── playwright.config.ts  # or cypress
└── README.md
```

### 必須チェックリスト

#### テスト

- ユニットテストを実装します（Vitest / Jest）。
- コンポーネントテストを実装します（Storybook + Testing Library）。
- E2Eテストを実装します（Playwright）。
- 視覚回帰テストはオプションで導入します。

#### セキュリティ

- npm audit / pnpm audit を実行します。
- CSP ヘッダーを設定します。
- 依存ライブラリを自動更新します。
- 入力バリデーションを実装します（Zod 等）。

#### パフォーマンス

- Core Web Vitals を計測します。
- バンドルサイズを監視します。
- Lighthouse CI を導入します。
- 画像最適化を設定します。

#### アクセシビリティ

- axe-core で自動検査します。
- キーボードナビゲーションを確認します。
- ARIA 属性を適切に使用します。
- コントラスト比をチェックします。

## サーバーアプリケーションテンプレート

API サーバー・バッチ処理・マイクロサービスなど、サーバーサイドアプリケーション向けテンプレートです。

### ディレクトリ構成

```
server-app-template/
├── .github/
│   └── workflows/
│       └── ci.yml
├── docker/
│   ├── Dockerfile
│   ├── docker-compose.yml
│   └── Dockerfile.migrate   # DBマイグレーション用
├── cmd/
│   └── server/             # エントリポイント
├── internal/
│   ├── domain/             # ドメインモデル
│   ├── usecase/            # ビジネスロジック
│   ├── handler/            # HTTP / gRPC ハンドラ
│   ├── infrastructure/     # DB / Cache / 外部API
│   └── config/             # 設定管理
├── migrations/             # DBマイグレーション
├── tests/
│   ├── unit/
│   ├── integration/
│   └── load/               # 負荷テスト（k6 等）
├── docs/
│   └── api/                # OpenAPI 仕様
├── scripts/
│   └── setup.sh
├── .env.example
├── Makefile
└── README.md
```

### 必須チェックリスト

#### テスト

- ユニットテストを実装します（テーブル駆動推奨）。
- 統合テストを実装します（テストコンテナ使用）。
- 負荷テストを実装します（k6 / Locust）。
- 契約テストを実装します（OpenAPI 準拠確認）。

#### セキュリティ

- SQL インジェクション対策を実装します。
- 認証・認可ミドルウェアを設定します。
- レートリミットを設定します。
- ログをマスキングします（個人情報）。

#### 運用

- ヘルスチェックエンドポイントを用意します。
- メトリクスを出力します（Prometheus）。
- 構造化ログを出力します（JSON）。
- グレースフルシャットダウンを実装します。

#### データベース

- マイグレーションを管理します。
- 接続プールを設定します。
- トランザクションを管理します。
- インデックス設計をドキュメント化します。

## 言語別テンプレート対応マトリクス

| 言語 | Web テンプレート | Server テンプレート | 推奨ツールチェイン |
|---|---|---|---|
| TypeScript | Next.js / React | NestJS / Express / Hono | Biome, Vitest, Playwright, Prisma |
| Go | — | 標準 net/http / Echo / Gin | gofmt, go test, golangci-lint, sqlc |
| Python | Streamlit（簡易）/ React + FastAPI | FastAPI / Django / Flask | ruff, pytest, playwright, alembic |
| Rust | Leptos / Yew | Axum / Actix-web | clippy, cargo test, sqlx, criterion |
| Ruby | Rails View / Hotwire | Rails API / Sinatra | rubocop, rspec, brakeman, sidekiq |

## エージェント向けプロンプトテンプレート

エージェントに指示を与える際の標準プロンプト構造です。この形式を使うことで、一貫した品質でアプリケーションを生成できます。

### プロンプト構造

1. アプリケーション種別を指定します（Web / Server / Fullstack）。
2. 使用言語・フレームワークを指定します。
3. 機能要件を列挙します（ユースケース一覧）。
4. 非機能要件を指定します（パフォーマンス・セキュリティ・可用性）。
5. テンプレート適用を指示します（CI・コンテナ化・セキュリティチェックを含める）。
6. 出力形式を指定します（ディレクトリ構成・ファイル内容・セットアップ手順）。

### プロンプト例

```
以下の要件を満たすサーバーアプリケーションを作成してください。

【種別】REST API サーバー
【言語】Go 1.23
【フレームワーク】Echo
【機能要件】
- ユーザー登録・ログイン（JWT認証）
- タスクの CRUD 操作
- タスク一覧のページネーション

【非機能要件】
- レスポンス時間: P99 < 200ms
- テストカバレッジ: 70% 以上
- コンテナ対応（マルチステージビルド）

【テンプレート適用】
- GitHub Actions CI（テスト・Lint・セキュリティスキャン）
- Docker / docker-compose 構成
- Trivy によるコンテナスキャン
- OpenAPI 仕様書の生成
- 構造化ログ・メトリクス対応

【出力】
- ディレクトリ構成
- 主要ソースコード
- CI 設定ファイル
- Docker 関連ファイル
- README（セットアップ手順含む）
```

## 今後の拡張計画

### テンプレートの実ファイル化

各言語・フレームワークごとに、実際に動作するテンプレートリポジトリを作成し、Cookiecutter / degit 等で利用できる形にします。

### エージェント用スキーマ定義

プロンプトを JSON Schema 化し、エージェントが要件を構造化して解釈できるようにします。

### カスタムルールの追加

プロジェクト固有の追加要件（特定クラウドプロバイダ、監視ツール、メッセージキュー等）を差し込める拡張ポイントを設計します。

## まとめ

共通基盤要件、Web / サーバー別テンプレート、言語別マトリクス、プロンプト構造をそろえることで、エージェントは一貫した品質でアプリケーションを生成できます。今後はテンプレートの実ファイル化とスキーマ定義を進めます。
