description: content/draft/ の下書きを content/ のノートへ昇格する
---

`content/draft/` の下書きノートを、`content/` のノート標準形へ変換して `content/` に保存します。

## 対象ノートの決定

- `$1` にファイル名またはパスが指定されていれば、そのノートを対象とします。
- 未指定の場合は、`content/draft/` 配下の候補を提示してください。候補が1件のみならそれを採用し、複数件ならユーザーに選択させてください。

content/draft/ 配下の候補:
!`ls -1 content/draft 2>/dev/null`

内部リンクのリンク先候補となる content/ のノート:
!`ls -1 content/*.md 2>/dev/null | sed 's|^content/||; s|\.md$||'`

## 変換ルール

`content/` のノート標準形は「frontmatter → `## 概要` → 本文 → `## 参考情報`」です。draft の意味内容を変えずに、この標準形へ整形してください。

1. **frontmatter を付与する**
   - `tags`: 内容から推測したタグを5個以内。既存ノートに合わせて英語の kebab-case / 小文字単語（例: `https`, `ssl`, `certificate`, `network`, `security`）を基本とし、日本語タグは既存ノートに既にあるものだけを使う（例: `自動化`, `管理`, `スケジューリング`）。
   - `created`: 実行日（YYYY-MM-DD）。

2. **H1 を削除する**
   - `content/` ではファイル名がタイトルとして使われるため、H1 は残さない。H1 の内容は `## 概要` の材料にする。

3. **見出しの先頭番号を除去する**
   - `## 0. 全体像` → `## 全体像`、`## 1. Mac 側の準備` → `## Mac 側の準備`、`### 3-1. macOS（Mac 本体）` → `### macOS（Mac 本体）` のように、番号だけを落とす（階層は保つ）。

4. **セクション間の `---` を削除する**
   - 本文中に残っている区切り用の水平罫線は取り除く。

5. **`## 概要` を作る**
   - draft の冒頭ブロック（`> 対象：` / `> 目的：` などのblockquote）や導入文を、1〜2文に要約して `## 概要` とする。`content/` の既存ノートと同じ簡潔さ（1〜2文）に収める。

6. **本文を知識ノートの体裁に整える**
   - 意味・情報量・手順の順序は保持する。理解を変える書き換えは避ける（文体の統一は除く）。
   - 表・コードブロック・callout（`> [!tip]` 等の形式）・画像参照はそのまま保持する。
   - 末尾に `## まとめ` を追加する（draft 側に同趣旨の章がある場合は流用・再構成して置き換える）。

7. **文体をですます調に統一する**
   - 本文・箇条書き・表内の説明文は「です・ます」で終える（例: 「〜します」「〜です」）。
   - draft が常体（だ・である調）でも、意味を変えずにですます調へ変換する。
   - 見出し・表の項目名などの体言止めはそのままでよい。
   - コードブロック・コマンド・設定値・引用文は変更しない。

8. **`## 参考情報` を追加する**
   - 末尾に以下を配置する（`content/` の既存ノートと同じ形式）:

   ```markdown
   ## 参考情報

   ### 参照元

   | ソース           | URL                 | 内容       |
   | ---------------- | ------------------- | ---------- |
   | 公式ドキュメント | https://example.com | 内容の説明 |

   ### 関連項目

   - [[既存のcontentノート名]] - 関連する理由
   ```

   - 参照元は draft 内で言及されている外部の公式ドキュメント・URL を記載する。URL が特定できない項目は `|` を空欄にして記載するか、省略してよい。
   - 関連項目は上記「リンク先候補」に実在するノートのみ `[[...]]` でリンクする。存在しないノート名は作らない。

## 保存

- 保存先: `content/<ファイル名>.md`
- **ファイル名は日本語を推奨**する。既存ノートの命名（例: `OpenWrt技術ノート`, `Bitwarden SSH Agent と SSH の動作メカニズム`）に合わせ、英語スラッグの draft（例: `systemd-timer-guide.md`）は H1 や内容をもとに日本語化した名前（例: `systemd timer入門・運用メモ.md`）を提案する。
  - 製品名・技術名などの固有名詞は原綴りのままでよい。
  - 区切りはハイフンやアンダースコアではなく、日本語の助詞・中黒・「入門」「まとめ」などを使う。
  - 候補は2〜3案を提示し、ユーザーに選ばせてもよい。
- 同名ファイルが既に存在する場合は上書きせず、ユーザーに「別名保存 / 上書き / 中止」を確認する。
- 保存前に、変換後の Markdown 全文を提示して確認を得ること。

## draft の扱い

- `content/` への保存と内容確認を終えたうえで、**「draft を削除しますか？」とユーザーに確認する**。
- 肯定応答があった場合のみ `content/draft/<draft のファイル名>` を削除する。確認が得られない場合は draft を残す。

## 完了通知

- 作成したノートのパス
- 付与したタグ
- 追加した内部リンク
- draft を削除したか残したか
