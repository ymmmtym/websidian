このリポジトリの `content/` を**読み取り専用**で監査してください。ノート・添付・設定ファイルを編集、作成、削除しないでください。

## 1. 対象の決定

- `$ARGUMENTS` が空でない場合、その値（絶対パス、`~/...`、`content/` からの相対パス、またはファイル名）を対象にしてください。
  - ファイルなら1件、ディレクトリなら配下の `.md` を再帰対象にしてください。
  - 同名候補が複数ある場合は勝手に選ばず、候補を提示してユーザーに確認してください。
  - 存在しない場合は、content/ 内の類似ファイル名を提示して停止してください。
- `$ARGUMENTS` が空の場合、content/ 全体の `.md` を対象にしてください。
- `.obsidian/`、`.DS_Store`、バイナリ添付、`無題のファイル.md`、`無題のファイル.base` は監査対象から除外してください。ただし添付リンクの存在確認には使ってください。
  - `無題のファイル.md` と `無題のファイル.base` は空の残骸として扱い、検出・報告・削除の推奨を行わないでください。
- 本文だけでなく、ファイル名・フォルダ名・frontmatter（`aliases`, `author`, `owner` など）も確認してください。
- `content/draft/` は下書きなので誤検知は低優先として扱ってください。ただし個人情報・秘密情報の検出は通常どおり報告してください。

対象ノート一覧:

!`find content -type f -name '*.md' -not -path '*/.obsidian/*' -not -name '無題のファイル.md' | sort`

## 2. 検査の進め方

1. まず `rg` で候補を抽出してください。
2. 候補ごとに該当行の前後を読み、コードブロック・例示・プレースホルダーかどうかを判断してください。
3. 文脈を確認してから個人情報・秘密情報と判定してください。正規表現の一致だけで断定しないでください。
4. 検出した生値（パスワード、トークン、メールアドレス等）は最終レポートにそのまま書かず、必ずマスクしてください。

以降の `$V` は、対象指定がある場合はそのパス（ファイルまたはディレクトリ）に置き換えてください。

### 2-1. 個人情報

```bash
V="content"

# メール・電話・郵便番号
rg -n -H --hidden --no-ignore --glob '*.md' --glob '!.obsidian' \
  -e '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}' \
  -e '(\+81[ -]?)?0\d{1,4}[- ]?\d{1,4}[- ]?\d{3,4}' \
  -e '〒?\s?\d{3}[- ]?\d{4}' \
  "$V"

# 住所・氏名・生年月日・ID類
rg -n -H --hidden --no-ignore --glob '*.md' --glob '!.obsidian' \
  -e '(都|道|府|県).{0,10}(市|区|町|村).{0,30}(丁目|番地|号|\d+-\d+-\d+)' \
  -e '(マンション|アパート|ハイツ|コーポ|邸|方)' \
  -e '(氏名|お名前|担当者|宛名|生年月日|誕生日)' \
  -e '(社員番号|学籍番号|顧客番号|会員番号|顧客ID|アカウントID|ユーザーID)' \
  -e '(様|さん|氏|殿)\s*$' \
  "$V"

# マイナンバー・カード・口座
rg -n -H --hidden --no-ignore --glob '*.md' --glob '!.obsidian' \
  -e '(マイナンバー|個人番号).{0,20}\d{12}' \
  -e '(カード番号|クレジットカード).{0,20}\d{4}[- ]?\d{4}[- ]?\d{4}[- ]?\d{4}' \
  -e '(銀行|支店|口座番号|振込先)' \
  "$V"

# ネットワーク・端末情報
rg -n -H --hidden --no-ignore --glob '*.md' --glob '!.obsidian' \
  -e '\b(?:\d{1,3}\.){3}\d{1,3}\b' \
  -e '\b(?:[0-9A-Fa-f]{2}:){5}[0-9A-Fa-f]{2}\b' \
  -e '(SSID|ssid)\s*[:=]' \
  -e '(hostname|ホスト名|デバイス名|シリアル|UDID)' \
  -e '\.(local|lan|internal|home)\b' \
  -e '(緯度|経度|latitude|longitude|GPS)' \
  "$V"

# ローカルパス・URL 内の認証情報・クエリトークン
rg -n -H --hidden --no-ignore --glob '*.md' --glob '!.obsidian' \
  -e '/Users/[^/[:space:]]+|/home/[^/[:space:]]+' \
  -e '://[^/[:space:]:@]+:[^/[:space:]@]+@' \
  -e '[?&](token|key|sig|signature|access_token|api_key)=' \
  -e 'X-Amz-(Credential|Signature)' \
  "$V"
```

実行環境の識別子も検索語に使ってください。

```bash
id -F 2>/dev/null
whoami
hostname
scutil --get ComputerName 2>/dev/null
git config --global user.name
git config --global user.email
```

得られた空でない値を `rg -F -H --hidden --no-ignore --glob '*.md' --glob '!.obsidian' -e '<値>' "$V"` で検索してください。対象が1ノートの場合はそのノートだけを検索し、対象がディレクトリの場合は隠しディレクトリ内の `content/draft/` も含めます。値が複数ある場合は `-e` を複数指定してください。これらの値はレポートではマスクしてください。

### 2-2. 秘密情報

```bash
V="content"

rg -n -H --hidden --no-ignore --glob '*.md' --glob '!.obsidian' \
  -e '-----BEGIN [A-Z ]*PRIVATE KEY-----' \
  -e '\bAKIA[0-9A-Z]{16}\b' \
  -e '\b(ghp|gho|ghu|ghs|ghr)_[A-Za-z0-9]{20,}\b' \
  -e '\bgithub_pat_[A-Za-z0-9_]{20,}\b' \
  -e '\bglpat-[A-Za-z0-9_-]{20,}\b' \
  -e '\bxox[baprs]-[A-Za-z0-9-]{10,}\b' \
  -e '\bsk-[A-Za-z0-9_-]{20,}\b' \
  -e '\bsk-ant-[A-Za-z0-9_-]{20,}\b' \
  -e '\bAIza[0-9A-Za-z_-]{30,}\b' \
  -e '\bsk_live_[A-Za-z0-9]{20,}\b' \
  -e '\beyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\b' \
  -e '(password|passwd|pwd|secret|api[_-]?key|client[_-]?secret|access[_-]?token|refresh[_-]?token|auth[_-]?token)\s*[:=]' \
  -e 'Authorization:\s*Bearer\s+' \
  -e '(postgres|postgresql|mysql|mongodb|mongodb\+srv|redis|amqp)://[^[:space:]]+:[^[:space:]@]+@' \
  -e '^[A-Z0-9_]*(KEY|TOKEN|SECRET|PASSWORD|PASS|PWD)[A-Z0-9_]*\s*=' \
  "$V"
```

秘密情報を検出した場合も、値をレポートへ転記せず「AWS アクセスキーらしき文字列」「DB 接続文字列」のように種類と位置だけを報告してください。

### 2-3. 内部リンク切れ

```bash
V="content"

# Wiki リンク
rg -n -o -H --hidden --no-ignore --glob '*.md' --glob '!.obsidian' '!?\[\[[^]]+\]\]' "$V"

# Markdown のローカルリンク（http/https/mailto/アンカーのみを除外）
rg -n -o -H --pcre2 --hidden --no-ignore --glob '*.md' --glob '!.obsidian' \
  '\[[^]]*\]\((?!https?://|mailto:|#)[^)]+\)' "$V"
```

各リンクについて以下を確認してください。

- `[[Note]]` / `[[Note|alias]]` は、content/ 内のファイル名で解決できるか。
- `[[Note#見出し]]` はリンク先ノートと見出しの両方が存在するか。
- `[[#見出し]]` は同じノート内に見出しが存在するか。
- `![[file.png]]` などの添付は content/ 内に実在するか。
- Markdown のローカルリンクは、ノートからの相対パスと `content/` ルートからの相対パスの両方で確認する。
- 同名ノートが複数あり解決が曖昧な場合は「曖昧」として報告する。
- 外部 URL の到達確認は行わない（ネットワークアクセスを発生させない）。

### 2-4. frontmatter 検証

各ノートの先頭が `---` で始まる場合、次の `---` までを frontmatter として扱い、以下を確認してください。

- 閉じ `---` が存在するか。
- YAML として明らかに不正でないか（タブ、重複キー、引用符の閉じ忘れなど）。
- `tags` が存在し、配列または文字列として妥当か。
- `created` が存在し、`YYYY-MM-DD` 形式か。
- タグの表記揺れ（大文字/小文字、空白、重複）がないか。

可能なら次の Ruby で機械的に検出してください。Ruby が使えない場合は目視で確認してください。

```bash
V="content"

find "$V" -type f -name '*.md' -not -path '*/.obsidian/*' -print0 | \
  xargs -0 ruby -ryaml -rdate -e '
    ARGV.each do |f|
      text = File.read(f, encoding: "UTF-8")
      next unless text.start_with?("---")
      parts = text.split(/^---\s*$\n?/, 3)
      if parts.length < 3
        puts "#{f}: frontmatter の閉じ --- がありません"
        next
      end
      begin
        data = YAML.safe_load(parts[1], permitted_classes: [Date, Time], aliases: true) || {}
        puts "#{f}: tags がありません" if data["tags"].nil?
        puts "#{f}: created がありません" if data["created"].nil?
        if data["created"] && data["created"].to_s !~ /\A\d{4}-\d{2}-\d{2}\z/
          puts "#{f}: created の形式が不正です"
        end
        unless data["tags"].nil? || data["tags"].is_a?(Array) || data["tags"].is_a?(String)
          puts "#{f}: tags の型が不正です"
        end
      rescue => e
        puts "#{f}: YAML エラー: #{e.message}"
      end
    end
  '
```

`content/draft/` の未設定項目は低優先として扱ってください。

### 2-5. 重複・類似ノート

```bash
V="content"

find "$V" -type f -name '*.md' -not -path '*/.obsidian/*' -print0 | \
  xargs -0 shasum | sort
```

- 同じハッシュのファイルは完全重複候補として報告してください。
- frontmatter を除いた本文が同じものも完全重複として扱ってください。
- ファイル名を正規化（空白・記号・大小文字を無視）して一致するものを報告してください。
- 見出し構成がほぼ同じノートは類似候補として報告してください。
- 重複・類似は削除せず、整理候補の提示だけにしてください。

### 2-6. 文体（ですます調）

`content/` 配下のノート本文がですます調で統一されているかを確認してください。

- 検出対象: 本文・箇条書きの文末が常体になっている箇所（`〜する。` / `〜である` / `〜だ。` / `〜ない。` など）。
- 除外: 見出し、表の項目名や名詞句のみのセル、コードブロック、引用、外部から引用した文章、`content/draft/`。
- 同一ノート内で敬体と常体が混在している場合は、その旨も記載してください。
- 重要度は **低** として扱ってください（内容の正確性には影響しないため）。
- 検出した文はそのまま引用し、推奨する文末（です・ます）を添えてください。

### 2-7. 誤検知の扱い

以下は原則として低優先または問題なしとしてください。ただし文脈上明らかに実データなら検出として扱ってください。

- コードブロックやインラインコード内の例示
- `example.com`、`example.org`、`192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24`、`localhost`、`0.0.0.0`
- `${...}`、`<YOUR_KEY>`、`xxx`、`dummy`、`test`、`your_` などのプレースホルダー
- `password = process.env.PASSWORD` のような環境変数参照
- 公式ドキュメントに記載されたサンプル値
- `content/draft/` の空欄・例示

### 2-8. 既知の無視対象（2026-11-24 合意）

以下は意図的な未解決リンクとして無視し、修正提案を含めない。`AGENTS.md` の「コンテンツ監査で合意した方針」も参照。

- 無視するリンク文字列（重複除外10件）: `コンテキスト`, `コーディングエージェント`, `チャットエージェント`, `コンテキストエンジニアリング`, `コンテキストウィンドウ`, `プロンプトエンジニアリング`, `エージェント設計`, `SSH Config ベストプラクティス`, `Bitwarden セキュリティ設定`, `WezTerm SSH 接続設定`
- これらはクリック時に 404 になっても許容する。スタブ記事の作成・リンク削除・グラフ改造は提案しない。
- 将来これらと同名のノートを公開したときは、この一覧から外す。
- 新しい未解決リンクが増えた場合は個別に判断し、この一覧を自動で拡張しない。

### マスク規則

- メール: `a***@example.com`
- 電話: `***-****-1234`
- IP: `192.168.***.***`（公開 IP も下位オクテットを隠す）
- 氏名: `山***`
- 住所: 都道府県・市区町村まで表示し、番地以下は `***`
- ローカルパス: `/Users/***/...`
- トークン・キー・パスワード: 値を出さず「AWS アクセスキー」「API トークン」「秘密鍵」などの種類のみ
- カード・マイナンバー: 値を出さず「カード番号らしき16桁」「12桁の個人番号らしき文字列」とのみ記載

## 4. 完了条件

- 対象ノートをすべて確認したこと。
- 高・中・低の判定理由を説明したこと。
- 内部リンク・frontmatter・重複の結果を報告したこと。
- 文体（ですます調）の確認結果を報告したこと。
- 検出した秘密情報の生値を表示していないこと。
- ファイルを一切変更していないこと。
- 修正が必要な場合に、ユーザーへ対象と方針の指定を求めていること。
