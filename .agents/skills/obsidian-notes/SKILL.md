# Obsidian ノート操作

Obsidian Vault（`content/`）に対するノート作成・監査・公開の手順を提供します。

## 前提

- リポジトリ直下をカレントディレクトリとして操作する。`content/` はリポジトリ直下にある。
- `content/` は Vault そのもの。`content/draft/` は Git 管理外・ビルド除外の下書き置き場。
- 詳細な手順は `.opencode/commands/obsidian/` に定義されている。**このスキルは手順を複製せず、そちらを唯一の情報源として参照する。**手順を変えるときは `.opencode/` 側を編集する。

## 操作の選択

| ユーザーの依頼                                    | 実行する手順                             |
| ------------------------------------------------- | ---------------------------------------- |
| チャットの内容をノートにまとめる                  | `.opencode/commands/obsidian/chat.md`    |
| `content/` を個人情報・秘密情報の観点で監査する   | `.opencode/commands/obsidian/check.md`   |
| `content/draft/` の下書きを `content/` へ昇格する | `.opencode/commands/obsidian/publish.md` |

依頼が曖昧な場合は、どの操作をしたいのか確認する。監査（`check`）と昇格（`publish`）は目的が逆向きなので取り違えない。

## 実行方法

1. 上表から該当するファイルを読む。
2. その手順に従って作業する。
3. 手順中のプレースホルダーを、ユーザーの依頼内容で置き換える。

| 手順ファイル中の記法          | 置き換える内容                                                                     |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `$ARGUMENTS`                  | ユーザーが指定した対象（パス・ファイル名）。未指定なら空のまま手順どおりに分岐する |
| `$1`                          | ユーザーが指定した第1引数（ファイル名など）                                        |
| `!`バッククォートで囲まれた行 | シェルコマンドの実行結果をその場に埋め込む指示。実際にコマンドを実行して結果を使う |

手順ファイル先頭の frontmatter（`agent: plan` など）は OpenCode 固有の設定であり、OpenHands では無視する。代わりに次節の制約に従う。

## 操作ごとの制約

### chat（ノート作成）

- 保存先は `content/<ファイル名>.md`。ファイル名は日本語を推奨する。
- 既存ファイルと同名になる場合は、上書きせずユーザーに確認する。
- 文体はですます調に統一する。見出しと表の項目名は体言止めでよい。
- コードブロック・コマンド・設定値は変更しない。

### check（監査）

- **読み取り専用。** ノート・添付・設定ファイルを作成、編集、削除しない。
- 検出した生値（パスワード、トークン、メールアドレス、氏名など）をレポートにそのまま書かない。必ずマスクする。
- 外部 URL への到達確認は行わない。ネットワークアクセスを発生させない。
- `AGENTS.md` の「コンテンツ監査で合意した方針」に記載された既知の未解決リンクは、指摘対象から除外する。

### publish（昇格）

- 変換後の Markdown 全文をユーザーに提示し、確認を得てから保存する。
- 同名ファイルが存在する場合は上書きせず確認する。
- `content/draft/` の削除は、保存完了後にユーザーの明示的な同意を得てから行う。
- 添付は `content/draft/` に残したままでは公開されない。`content/` 配下へコピーし、参照パスを保存先ノートからの相対パスへ更新する。

## 完了時の報告

手順ファイルの「完了通知」「レポート形式」の指定に従う。加えて、変更したファイルの一覧を日本語で簡潔に伝える。
